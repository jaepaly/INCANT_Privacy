# 개인정보 영향평가 (DPIA)

## 자유 텍스트를 외부 생성형 AI로 처리하는 게임 서비스

> **To-Be 문서**입니다. 상용화를 가정한 INCANT을 대상으로 하며,
> 가정의 근거는 [01_policy_benchmark.md](01_policy_benchmark.md)와
> [02_service_model.md](02_service_model.md)에 있습니다.

| 항목 | 내용 |
|---|---|
| 대상 처리 | 이용자가 자유롭게 입력한 문장을 외부 LLM으로 전송해 의미를 판정하는 처리 |
| 컨트롤러 | INCANT 운영자 (가정) |
| 작성 기준 | GDPR Art.35(7) 각 호 |
| 임계 판단 기준 | WP248 rev.01 (WP29, 2017-04-04 채택 / **2017-10-04 최종 개정**) |
| 작성일 | 2026-08-11 |
| 문서 버전 | v0.1 |

### 이 문서를 GDPR 형식으로 쓰는 이유

국내 개인정보 보호법 **제33조(개인정보 영향평가)**를 원문으로 확인한 결과,
**제1항의 실시 의무는 공공기관에 부과**되며 민간 개인정보처리자에 대해서는
**"영향평가를 하기 위하여 적극 노력하여야 한다"**는 노력 의무입니다.

즉 민간 게임 서비스에 국내법상 강제 의무는 없습니다. 반면 GDPR Art.35는 요건에
해당하면 **처리 전에 반드시** 수행해야 합니다. 따라서 **요구 수준이 높은 GDPR 형식으로
작성하면 국내 자율 영향평가까지 함께 커버**됩니다.

### 선례 부재

[벤치마크](01_policy_benchmark.md) §4에서 확인한 대로, 국내 주요 게임사 6곳 12개
처리방침 어디에도 **생성형 AI·자유 입력 텍스트 처리에 관한 기재가 없습니다.**
참고할 만한 공개 사례가 확인되지 않아, 이 문서는 조문과 가이드라인에서 직접 도출했습니다.

## 1. 임계 판단 — DPIA가 필요한가

Art.35(1)은 *"특히 신기술을 사용하는 처리 유형이 (…) 자연인의 권리와 자유에 **높은 위험을
초래할 가능성이 있는 경우**, 컨트롤러는 처리 **전에** 영향평가를 수행하여야 한다"* 고
규정합니다.

WP248 rev.01은 그 판단을 위한 **9개 기준**을 제시하고,
*"대부분의 경우 **두 개 기준**에 해당하면 DPIA가 필요하다고 볼 수 있으며, 더 많은 기준에
해당할수록 높은 위험일 가능성이 크다"* 고 봅니다.

| # | WP248 rev.01 기준 | 해당 | 근거 |
|---|---|---|---|
| 1 | 평가 또는 스코어링 (프로파일링·예측 포함) | ✅ | 기억하는 보스가 이용자의 원소·형태 선호와 행동 통계로 행태 프로파일을 구성 (`PD-010`, `PD-011`). 광고식별자 기반 맞춤형 광고 (`PD-019`) |
| 2 | 법적 효력 또는 그에 준하는 중대한 영향을 갖는 자동화된 결정 | ⚠️ **유보** | `blocked` 판정이 주문을 차단하고 제재로 이어질 수 있으나, 게임 서비스 이용 제한이 Art.22의 "similarly significantly affects"에 해당하는지는 다툼의 여지가 있음. **판단하지 않음** |
| 3 | 체계적 모니터링 | ✅ | 게임 플레이 전반의 행위 로깅과 부정이용 탐지 (`PD-018`, `PD-020`, `V-08`) |
| 4 | 민감정보 또는 고도로 사적인 성격의 정보 | ✅ | 자유 텍스트 채널(`CH-01`, `CH-02`)로 Art.9 특별범주 정보가 비의도적으로 유입될 수 있음. 고객센터 첨부파일(`CH-03`)도 동일 |
| 5 | 대규모 처리 | ✅ (가정) | 상용 게임 서비스를 가정. WP248의 4요소 — 정보주체 수, 데이터의 양과 범위, 처리의 지속성, 지리적 범위 — 중 **지속성**(계정 존속 기간)과 **지리적 범위**(글로벌 서비스)가 특히 해당 |
| 6 | 데이터셋의 결합·대조 | ✅ | 게임 기록 + 결제 + 광고식별자 + 제재 이력이 하나의 계정에 결합 |
| 7 | 취약한 정보주체 | ✅ | WP248이 **아동**을 명시적으로 예시. 게임은 아동 이용자 비중이 구조적으로 높음 |
| 8 | **혁신적 이용 또는 새로운 기술·조직적 솔루션의 적용** | ✅ ★ | **이 처리의 본질.** 이용자가 자유롭게 쓴 문장을 외부 생성형 AI로 실시간 전송해 의미를 판정한다. WP248은 신기술 사용이 DPIA 필요성을 촉발할 수 있다고 명시하며, 그 이유로 *"신기술 도입의 개인적·사회적 영향이 알려지지 않았을 수 있음"* 을 든다 |
| 9 | 처리 자체가 권리 행사나 서비스·계약 이용을 방해하는 경우 | ✅ | 국외 이전을 거부하면 판정 기능이 제공되지 않는다(서비스 모델 §5.2). 연령 게이트 미통과 시 가입 불가 |

### 판단

**9개 기준 중 최소 7개에 해당합니다.** WP248의 "두 개면 대체로 필요" 기준을 크게 상회하며,
특히 **기준 8(신기술)과 기준 4(민감정보)의 결합**이 이 처리의 위험 성격을 규정합니다.

→ **DPIA가 필요합니다.** Art.35(1)에 따라 **처리 개시 전에** 수행되어야 합니다.

> 기준 2는 유보했습니다. 게임 이용 제한이 Art.22의 "중대한 영향"에 해당하는지는
> 해석이 갈릴 수 있고, 7개만으로도 임계는 충분히 넘습니다. **불확실한 것을 세어
> 결론을 부풀리지 않습니다.**

## 2. 처리의 체계적 기술 — Art.35(7)(a)

### 2.1 처리 개요

| | |
|---|---|
| 처리 활동 | 자유 텍스트 주문의 의미 판정 |
| 대상 정보 | `PD-008` 주문 입력 원문 — 이용자가 게임 내에서 자유롭게 작성한 문장 (최대 60자) |
| 처리 목적 | 입력 문장의 의미를 구조화된 게임 효과(SpellSpec)로 변환 |
| 처리 주체 | INCANT 운영자 (컨트롤러) / Google — Gemini API (`V-02`, 관계 미확정) |
| 처리 위치 | 판정 게이트웨이 `SYS-04` (국내) → Gemini API (**미국**) |
| 정보주체 | 게임 이용자. 아동 포함 가능 |

### 2.2 데이터 흐름

```text
이용자 입력 (자유 텍스트)
      │
      ▼
[CTRL-001] 전송 전 개인정보 필터 ── 차단 ──→ 이용자에게 사유 고지, 전송 중단
      │
      │ (통과 또는 마스킹)
      ▼
판정 게이트웨이 SYS-04 (국내)
      │
      │  ★ 국경 — 제28조의8 / GDPR Chapter V 적용
      ▼
Google Gemini API (미국)
      │
      ▼
판정 결과 (구조화)  ──→ PD-009로 저장   ※ 원문(PD-008)은 저장하지 않음
```

### 2.3 이 처리의 고유한 성격

**① 입력 내용을 사전에 특정할 수 없습니다.**
정형 필드가 아니라 자유 문장입니다. 무엇이 전송될지 컨트롤러가 알 수 없습니다.

**② 처리 결과가 결정적이지 않습니다.**
같은 입력이 항상 같은 판정을 내지 않습니다. 이는 게임 설계상 의도된 것이지만,
처리의 예측 가능성이라는 관점에서는 통상적인 처리와 다릅니다.

**③ 수령자가 자기 목적으로 이용할 여지가 있습니다.**
`V-02`의 관계(위탁 vs 제3자 제공)가 확정되지 않았습니다. 이는 Google이 입력을
모델 품질 개선 등 자기 목적으로 쓰는지에 달려 있으며, **U-01로 미확인** 상태입니다.

### 2.4 처리 근거 (Art.6)

**미확정입니다.** `V-02`의 관계가 확정되어야 결정됩니다.

| `V-02` 관계 | 국내 | EU |
|---|---|---|
| 위탁 | 별도 동의 불요, 수탁자 공개 + 계약 | 처리자(processor) — Art.28 계약 |
| 제3자 제공 | 별도 동의 필요 | 컨트롤러 간 이전 — 별도 근거 필요 |

## 3. 필요성·비례성 평가 — Art.35(7)(b)

### 3.1 목적의 정당성

이 처리는 서비스의 **핵심 기능 그 자체**입니다. 자유 문장을 게임 효과로 바꾸는 것이
INCANT의 존재 이유이며, 부수적 목적이 아닙니다.

### 3.2 대안 검토

| 대안 | 개인정보 관점 | 실현 가능성 | 채택 |
|---|---|---|---|
| **A. 로컬 규칙 기반 판정** | 국외 이전 없음. 최선 | 구현되어 있음(`MockJudge`). 다만 의미 판정 품질이 크게 낮아 서비스 핵심 가치가 성립하지 않음 | 기본값으로는 부적합 |
| **B. 온프레미스 LLM** | 국외 이전 없음 | 운영 비용·품질 문제. 소규모 사업자에게 현실성 낮음 | 미채택 |
| **C. 외부 LLM + 최소화 조치** | 이전은 남으나 유입·저장을 최소화 | 구현 가능 | **채택** |
| **D. 외부 LLM, 조치 없음** | As-Is 상태 | — | 미채택 |

### 3.3 채택한 최소화 조치와 비례성

| 조치 | 효과 | 상태 |
|---|---|---|
| 입력 60자 제한 | 전송량 및 유입 가능 정보의 범위 축소 | 구현됨 (원래는 비용 목적이나 부수 효과가 있음) |
| **원문 미보관** | 저장 측 위험을 구조적으로 제거 | 설계 채택 (서비스 모델 §5.4) |
| **CTRL-001 전송 전 필터** | 정형 식별자 차단·마스킹 | **구현·테스트 완료** |
| **거부 시 로컬 판정 폴백** | 이전 거부가 서비스 배제로 직결되지 않게 함 | 설계 채택 (§5.2) |

### 3.4 비례성 판단

목적 달성에 **전송 자체는 불가피**합니다. 외부 판정 없이는 서비스가 성립하지 않습니다.

다만 전송되는 **내용의 범위**는 축소 가능하며, 위 조치들이 그 축소를 수행합니다.
저장 측은 미보관으로 제거되었고, 전송 측은 정형 식별자에 한해 차단됩니다.

**남는 불비례 요소**: 특별범주 정보의 유입은 여전히 통제되지 않습니다(§4 R-01).
따라서 **현재 상태의 비례성은 완전히 확보되지 않았습니다.**

## 4. 정보주체의 권리·자유에 대한 위험 — Art.35(7)(c)

Art.35(7)(c)가 요구하는 것은 보안 위험이 아니라 **정보주체의 권리와 자유에 대한 위험**입니다.

| ID | 위험 | 가능성 | 영향 | 위험도 | 잔여 위험 |
|---|---|---|---|---|---|
| **R-01** | 자유 텍스트를 통해 특별범주 정보가 유입되어 국외로 전송됨 | Medium | High | **HIGH** | **남음** |
| **R-02** | 이전 거부가 곧 서비스 배제로 이어져 권리 행사가 억제됨 | Medium | Medium | MEDIUM | 완화됨 |
| **R-03** | 아동 이용자의 자유 입력이 외부 AI로 전송됨 | Medium | High | **HIGH** | 부분 완화 |
| **R-04** | 행태 프로파일링(기억하는 보스)을 이용자가 인지하지 못함 | High | Low | MEDIUM | 완화 가능 |
| **R-05** | EU→KR→US 재이전 연쇄에서 보호 수준이 단절됨 | Medium | High | **HIGH** | **남음** |
| **R-06** | LLM 제공자가 입력을 보관하거나 학습에 이용함 | **미확인** | High | **판단 불가** | **미확인** |

### R-01 · 특별범주 정보의 비의도적 국외 전송

가장 다루기 어려운 위험입니다.

`CTRL-001`은 정형 식별자만 탐지합니다. Art.9가 열거하는 것 — 인종·민족적 출신,
정치적 견해, 종교적·철학적 신념, 노동조합 가입, 유전자·생체인식정보, 건강,
성생활·성적 지향 — 은 **정규식과 검사숫자로 잡을 수 있는 종류가 아닙니다.**

이 사실은 룰 엔진 출력에도 그대로 드러납니다 — `EU-SPC-001`이 `CH-01`·`CH-02`에서
계속 발동합니다([reports/findings_tobe.md](../../reports/findings_tobe.md)).

> **As-Is와 To-Be의 차이가 여기서 결정적입니다.** As-Is에서는 계정이 없어 결합 용이성이
> 낮아 `F-005`를 LOW로 평가했습니다. To-Be에는 계정·닉네임·결제정보가 있어 **같은 입력이
> 식별된 개인에게 직접 결합**됩니다. 위험도가 뒤집힙니다.

### R-03 · 아동 이용자

WP248이 아동을 취약한 정보주체로 명시합니다. 연령 게이트가 도입되어도
**게이트를 통과한 아동(만 14세 이상 / EU 회원국 기준 13~16세 이상)의 자유 입력은
그대로 외부로 전송**됩니다. 연령 확인은 이 위험을 제거하지 못하고 경계만 그립니다.

### R-06 · 판단 불가

Gemini API의 입력 보관·학습 이용 정책을 확인하지 못했습니다(**U-01**).

**이 항목은 위험도를 산정하지 않습니다.** 가능성을 모르는 채로 숫자를 붙이면
그럴듯하지만 근거 없는 평가가 됩니다. 확인 후 재평가합니다.

통제가 구현되어 인벤토리 필드가 채워지면 해당 Finding 후보가 사라집니다.
**이 DPIA와 [reports/](../../reports/)는 같은 상태를 다른 층위에서 보고 있습니다.**

## 6. 잔여 위험과 사전 협의 — Art.36

Art.36(1):

> "컨트롤러는 Art.35에 따른 DPIA가 **위험을 완화하기 위한 조치가 없는 상태에서**
> 처리가 높은 위험을 초래할 것임을 나타내는 경우, 처리 **전에 감독기구와 협의**하여야 한다."

### 판단

**현 시점에서 사전 협의 필요 여부를 확정할 수 없습니다.**

- **R-01(특별범주)** 은 조치 후에도 잔여 위험이 HIGH로 남습니다
- **R-06**은 가능성 자체가 미확인이라 위험도를 산정하지 못했습니다

**U-01(Gemini API의 입력 보관·학습 이용)이 확인되기 전에는 판단이 불가능합니다.**
그 답에 따라 R-06의 위험도가 정해지고, R-01의 잔여 위험 평가도 달라집니다.

→ **선행 과제: U-01 확인.** 이것이 이 DPIA에서 도출된 가장 우선순위 높은 조치입니다.

> 결론을 내릴 수 없다는 것도 결론입니다. "조치를 했으므로 괜찮다"고 쓰는 것이
> 이 단계에서 가장 위험한 서술입니다.

## 7. 정보주체 의견 청취 — Art.35(9)

Art.35(9)는 적절한 경우 정보주체 또는 그 대표자의 의견을 구하도록 합니다.

**수행하지 않았습니다.** 대상이 실재하지 않는 상용 서비스이므로 의견을 구할 정보주체가
없습니다. 실제 서비스라면 이 절은 공란으로 두어서는 안 되며, 최소한 청취하지 않은
사유를 기재해야 합니다.

## 8. 재검토 — Art.35(11)

Art.35(11)은 처리로 인한 위험이 변경되는 경우 등에 재검토를 요구합니다.

| 재검토 촉발 조건 | |
|---|---|
| `V-02`의 관계(위탁/제3자 제공) 확정 | §2.4·§6의 판단이 바뀜 |
| LLM 제공자·모델 변경 | 처리 조건이 달라짐 |
| 자유 텍스트 채널의 신설·변경 | §1 임계 판단 재수행 |
| `CTRL-001` 탐지 범위 확대 | R-01 잔여 위험 재평가 |
| 서비스 지역 확대 | 관할 추가 |

## 9. 국내 영향평가와의 관계

| | 국내 (제33조) | EU (Art.35) |
|---|---|---|
| 실시 의무 | **공공기관** (제1항) | 요건 해당 시 **의무** |
| 민간 사업자 | "적극 노력하여야 한다" — **노력 의무** (제11항) | 동일하게 의무 |
| 판단 기준 | 대통령령으로 정하는 기준의 개인정보파일 | Art.35(3) + WP248 rev.01 9개 기준 |
| 결과 제출 | 보호위원회에 제출 | 제출 의무 없음. 고위험 잔존 시 Art.36 사전 협의 |

**이 문서는 GDPR 형식으로 작성되었으므로 국내 자율 영향평가의 내용 요건도 충족합니다.**
다만 국내 영향평가는 제출 절차와 평가기관 지정 등 형식 요건이 별도로 있으므로,
실제 수행 시에는 시행령과 고시를 확인해야 합니다(**U-14**).
