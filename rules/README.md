# 컴플라이언스 룰 카탈로그

## 이 디렉터리의 원칙

**룰 하나에 근거 조문 하나 이상.** 근거 조문이 없는 룰은 그냥 `if` 문입니다. 조문 없이는 카탈로그에 넣지 않습니다.

**조문은 원문으로 검증합니다.** 기억이나 LLM 답변을 근거로 쓰지 않습니다. 각 `legal_basis` 항목은 `verification` 상태를 가지며, `확인필요` 상태의 조문은 카탈로그 하단에 미검증 목록으로 자동 집계됩니다.

| 상태 | 의미 |
|---|---|
| `확인필요` | 초안. 원문 대조 전 |
| `확인완료` | 원문 대조 완료. `checked_at`·`source` 필수 |

검증 출처:
- 국내 — [국가법령정보센터](https://www.law.go.kr/)
- EU — [EUR-Lex](https://eur-lex.europa.eu/), [EDPB 가이드라인](https://www.edpb.europa.eu/)

## 파일

| 파일 | 역할 |
|---|---|
| `kr.yaml` | 국내 개인정보 보호법 기준 룰 — **원본** |
| `eu.yaml` | GDPR 기준 룰 — **원본** |
| `CATALOG.md` | 사람이 읽는 카탈로그 — **생성물. 직접 수정 금지** |

`CATALOG.md`는 `tools/render_rules.py`가 YAML에서 생성합니다. 손으로 고치면 다음 생성 때 덮어써지고, 무엇보다 원본과 문서가 어긋납니다. 룰을 고칠 때는 YAML만 고치고 다시 생성하세요.

```bash
python tools/render_rules.py
```

## ID 체계

```
{관할}-{영역}-{일련번호}
   KR   TRF     001
```

관할: `KR` | `EU`

| 영역 | 코드 | 범위 |
|---|---|---|
| 투명성 | `TRP` | 처리방침, 고지, 정보 제공 |
| 국외이전 | `TRF` | 국경 간 이전, 재이전 |
| 보유·파기 | `RET` | 보유기간, 파기 절차 |
| 정보주체 권리 | `RGT` | 열람·정정·삭제·처리정지 |
| 특별범주 | `SPC` | 민감정보 / special categories |
| 아동 | `AGE` | 연령 확인, 법정대리인 동의 |

같은 쟁점의 KR·EU 룰은 `related` 필드로 상호 참조합니다.

## 룰 스키마

```yaml
- id: KR-TRP-001                # {관할}-{영역}-{번호}
  domain: 투명성                 # 위 영역 표 기준
  title: 짧은 제목
  summary: 한 문장 요약

  legal_basis:                  # 1개 이상 필수
    - law: 개인정보 보호법
      article: 제30조 제1항
      note: 조문이 요구하는 바
      verification: 확인필요      # 확인필요 | 확인완료
      checked_at: null          # 확인완료면 YYYY-MM-DD
      source: null              # 확인완료면 URL

  condition_human: |            # 사람이 읽는 판정 조건
  check_expr: |                 # 기계 판정용 표현식 (초안)
  severity_base: HIGH           # CRITICAL | HIGH | MEDIUM | LOW
  severity_rationale: |         # 왜 이 등급인지
  applies_to: [A-01, B-01]      # 흐름표 항목 ID
  remediation: []               # 개선 조치
  evidence: []                  # 이행을 입증할 증적
  related: [EU-TRP-001]
  notes: |                      # 선택 — 판단 유보, 해석 쟁점
```

### `severity_base`에 대한 주의

`severity_base`는 **룰 자체의 기본 심각도**이며 최종 위험도가 아닙니다. 최종 위험도는 `Likelihood × Impact`로 대상별 평가 단계에서 산출되며, 같은 룰이라도 대상에 따라 달라집니다.

### `check_expr`에 대한 주의

**현재 실행되지 않습니다.** 평가 데이터 모델이 아직 확정되지 않았습니다. 판정 로직의 의도를 지금 고정해두기 위한 초안 표현식이며, 데이터 모델 확정 시 실제 실행 가능한 형태로 옮깁니다.

## 관할 축에 대해

룰 모델에 관할 축을 둔 목적은 **"국내 기준 통과 / EU 기준 위반"** 구간을 갭으로 드러내는 것입니다.

다만 현재 As-Is(INCANT 데모)는 통제가 사실상 전무해서 **양 관할에서 거의 모두 걸립니다.** 관할 분기의 실질적 가치는 통제가 설계된 To-Be 단계에서 나옵니다 — 예: 만 14세 기준으로 설계한 연령 게이트가 국내는 통과하지만 EU 회원국 기준(16세, 하향 시 13세)에서는 갈리는 지점.

As-Is 단계에서 관할별 차이가 드러나는 부분은 **위반 여부가 아니라 요구 수준**입니다. 예를 들어 처리방침의 경우, 양쪽 다 미비이지만 GDPR Art.13이 요구하는 고지 항목이 더 구체적입니다. 각 룰의 `notes`에 해당 차이를 기록합니다.

## 현재 범위

이번 배치는 As-Is 흐름표(`docs/as-is/01_data_flow_asis.md`)에 직접 걸리는 6개 영역입니다.

다음 배치 예정:
- 처리 근거 (`LAW`) — 개인정보 보호법 제15조 / GDPR Art.6
- 처리위탁 (`VND`) — 제26조 / Art.28
- 접근권한·안전조치 (`SEC`) — 제29조 및 안전성 확보조치 기준 / Art.32
- 영향평가 (`DPA`) — Art.35
